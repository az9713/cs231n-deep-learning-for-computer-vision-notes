Lecture 11 · Systems for learning

Distributed training: make the whole machine useful

A larger cluster does not automatically make an experiment faster. The mathematical update, the placement of state, and the movement of bytes must agree.

Our inspection project now receives video from many factories. The model that learned from small images must process long clips and more diverse parts. Buying additional accelerators appears to solve the problem, until the program runs out of memory on every device or spends most of its time waiting for communication. This chapter develops a way to diagnose that situation. We will keep three questions separate: does the distributed algorithm compute the intended gradient, can its state fit, and how much useful work does the hardware perform?

The lecture uses Llama 3 as a documented large-model case, rather than as an architecture prescription for vision. The Llama 3 report provides a primary account of its training systems. Its 405B model belongs to the July 2024 release, distinct from the initial April 2024 Llama 3 release. Hardware specifications and scale examples below describe that historical setting; they are not a current purchasing comparison. The original inspection examples, proofs, and exercises are teaching constructions.

Compute is inseparable from memory 03:09

A graphics processing unit, or GPU, is a processor organized for extensive parallel work. Generating many pixels encouraged an architecture with many arithmetic units. Neural-network matrix multiplication can use those units because many output entries can be computed concurrently. This does not mean that a GPU is a uniformly faster CPU. Branch-heavy serial code may expose exactly the capabilities that a CPU optimizes more aggressively.

The H100 example illustrates a hierarchy: large high-bandwidth memory holds tensors, a smaller shared cache reduces repeated trips to that memory, and still smaller storage near each streaming multiprocessor supports active calculations. A streaming multiprocessor, or SM, groups execution resources; it is not equivalent to a single scalar CPU core. The lecture's H100 configuration has 132 active SMs and 80 GB of high-bandwidth memory. The NVIDIA Hopper tuning guide supplies architecture-specific details. Product variants and enabled resources matter when interpreting a diagram.

Registers and cache are different resources even when their capacities have similar numerical values. A register stores working values assigned to threads; a cache automatically retains recently accessed memory contents. Neither makes a large tensor disappear. A kernel that uses too many registers can reduce the number of simultaneously resident threads, so maximizing one local resource can reduce throughput elsewhere.

Tensor cores accelerate matrix operations using supported numerical formats. A fused multiply-add contributes two floating-point operations under the convention used here. Thus multiplying \(A\in\mathbb R^{m\times k}\) and \(B\in\mathbb R^{k\times n}\) costs approximately \(2mkn\) FLOPs. A FLOP is an operation; FLOP/s is a rate. Mixed precision often combines lower-precision inputs with higher-precision accumulation. It reduces memory traffic and can enable faster arithmetic, but numerical range, rounding, and kernel selection remain important. FP32 inputs do not universally imply that tensor cores are unavailable: modes such as TF32 make that a software-and-hardware-dependent question.

We can formalize the bottleneck without a benchmark. Let \(F\) be required operations, \(Q\) transferred bytes, \(P\) peak operations per second, and \(B\) memory bytes per second. Even an ideal implementation needs

\[t\geq\max(F/P,\ Q/B),\qquad I=F/Q,\qquad P_{\mathrm{attainable}}\leq\min(P,BI).\]

The ratio \(I\) is arithmetic intensity: operations performed per byte moved across the chosen memory boundary. Our hypothetical kernel uses \(10^{12}\) operations and transfers \(10^{10}\) bytes. At \(P=10^{15}\) FLOP/s and \(B=10^{12}\) bytes/s, compute needs at least 1 ms while movement needs 10 ms. Doubling peak arithmetic cannot remove the 10 ms bound. Reusing tiles of a matrix improves intensity by extracting more operations from each fetched block. These are lower bounds, not predictions that account for launch overhead or imperfect scheduling.

A cluster has several communication scales 15:09

A server groups accelerators connected by fast local links. Servers occupy racks; network switches connect racks and larger groups. The hierarchy is physical: cables, switches, storage, power, and cooling constrain it. A byte transferred within a processor is not interchangeable with a byte sent across a data center. The lecture's Llama example builds from eight GPUs per server to larger pods and a cluster of 24,576 GPUs. Its bandwidth figures are useful for relative scale, but peak link rates are not guaranteed application throughput, and directional versus aggregate bandwidth must be compared consistently.

For our factory dataset, decoding video and reading storage can be bottlenecks before a GPU starts computing. A profiler should separate storage wait, CPU preprocessing, host-to-device transfer, kernels, and collective communication. If every worker redundantly reads the same clip, adding workers wastes both statistical diversity and storage bandwidth. If one factory's videos are much longer, equal file counts do not imply equal work per worker.

The lecture also discusses TPUs, AMD accelerators, and AWS Trainium. The general reasoning survives a change of vendor: ask which matrix operations are fast, how much state fits, and what communication topology connects devices. Peak arithmetic alone omits compiler maturity, supported operators, precision, and the ability to overlap work. We will use GPU as the lecture's concrete example, while deriving algorithms independently of the particular product.

Data parallelism preserves a specified objective 28:43

Let \(W\) denote all trainable parameters, and let \(\ell(x;W)\) be one example's loss. There are \(M\) workers, each holding \(n\) different examples. The intended global mean loss is

\[L(W)=\frac1{Mn}\sum_{i=1}^{M}\sum_{j=1}^{n}\ell(x_{ij};W),\qquad \nabla_W L=\frac1M\sum_{i=1}^{M}g_i,\quad g_i=\frac1n\sum_{j=1}^{n}\nabla_W\ell(x_{ij};W).\]

Differentiation is linear, so each worker can compute its local mean gradient \(g_i\), then average gradients. Every worker begins with identical parameters and optimizer state. A collective operation called an all-reduce combines values and returns the result to every participant. After reduction, every replica applies the same update. No central machine needs to execute the complete model.

Exactness here refers to the same mathematical objective and batch, not bitwise equality across different reduction orders. Floating-point addition is not associative. Dropout randomness and operations that couple examples also deserve attention. In particular, batch normalization using local statistics is generally not the same computation as normalization over the global batch. The familiar statement that distributed data parallelism is just algebra is correct only after specifying these details.

Unequal batches expose an easy bug. If worker \(i\) has \(n_i\) examples and a local mean \(g_i\), the correct gradient is \(\sum_i n_i g_i/\sum_i n_i\). With local means 2 and 8 computed over batches of 3 and 1, respectively, the global mean is \(3.5\), not 5. For padded video, the intended denominator may be the number of valid frames or tokens rather than clips. Weight the gradients according to the actual loss definition.

The same reasoning permits gradient accumulation: process several microbatches at unchanged parameters, add appropriately normalized gradients, then update once. Updating after every microbatch follows a different trajectory. Increasing the global batch can also change optimization even if each individual distributed update is correct. The systems experiment must hold its statistical comparison fixed or explicitly report the change.

Overlap work without violating dependencies 33:01

During backpropagation, later layers produce parameter gradients first. Their gradients can be communicated while earlier layers continue computing. An earlier layer needs its local activation gradient from the chain rule; it need not wait for the global parameter gradient of every later layer. This distinction between activation gradients and parameter gradients explains why overlap is legal.

A collective has both latency and bandwidth cost. For an illustrative ring all-reduce of a gradient buffer containing \(S\) bytes across \(M\) workers, a simple model is

\[t_{\mathrm{ring}}\approx2(M-1)\alpha+ 2\frac{M-1}{M}\frac{S}{\beta},\]

where \(\alpha\) is a per-step latency and \(\beta\) is an effective link rate in bytes per second. Reduce-scatter distributes reduced chunks; all-gather then distributes those chunks to everyone. This is not a universal implementation formula: trees and topology-aware algorithms have other costs. It explains why “all-reduce is logarithmic” cannot be used as a complete bandwidth estimate.

With four workers, \(\alpha=10\) microseconds, \(S=100\) MB in decimal units, and \(\beta=10\) GB/s, the model gives \(0.00006+0.015=0.01506\) seconds. Hiding that behind useful backward work requires enough independent computation and suitable scheduling. Tiny communication buckets start early but pay more latency; huge buckets amortize latency but become ready late. Overlap is a measured property, not a consequence of simply launching asynchronous operations.

All workers must execute compatible collectives in compatible order. If one worker skips a backward pass because its batch has no valid labels while others reduce gradients, the program can hang. A correct implementation must represent that zero contribution within the agreed schedule. Asynchronous parameter updates are another legitimate algorithmic family, mentioned in the lecture, but they introduce stale parameters and different reproducibility properties; they are not a transparent replacement for the synchronous objective derived above.

Shard persistent state before changing the model 39:46

Replication becomes expensive when the model itself fills memory. Adam stores first and second moment estimates for each parameter, commonly named \(m\) and \(v\). The constants \(\beta_1,\beta_2\) control their averaging; they are not themselves the per-parameter optimizer state. We also need weights and gradients. A mixed-precision configuration may retain FP32 master weights and FP32 moments. Therefore an eight-byte-per-parameter estimate is a deliberately optimistic example, not a universal Adam memory rule.

Let \(P_w\) be the number of scalar parameters and \(b_s\) the total persistent state bytes per parameter. Replicated state requires \(b_sP_w\) bytes per worker. If \(P_w=10^9\) and \(b_s=16\), that is 16 GB before activations, temporary buffers, allocator overhead, and communication workspaces. Dividing a device's advertised capacity by this number does not establish the maximum trainable model.

ZeRO removes redundant optimizer, gradient, and parameter storage in successive stages. Fully sharded data parallelism distributes these states across workers while retaining data-parallel computation. Conceptually, before a layer executes, workers gather its parameter shards; each then computes on its own examples. Parameters can be discarded after use and gathered again for backward. Local gradients are reduced and scattered so each owner retains the global gradient for its shard.

The lecture illustrates ownership by assigning entire layer weights to a device. Real implementations can shard flattened parameter groups, so ownership need not coincide with whole layers. PyTorch's FSDP documentation describes the implementation contract. The distinction matters for predicting transient peaks: even if persistent state is evenly divided, a complete gathered group may briefly occupy memory.

For a group of \(K\) workers, an optimistic state term becomes \(b_sP_w/K\). Total peak memory is closer to this term plus live activations, gathered parameters, and workspaces. Prefetching the next layer helps overlap but increases simultaneous residency. Updating an owned parameter immediately is safe only after all uses of its old value and all contributions to its gradient are complete. Weight tying, gradient accumulation, and global gradient clipping can invalidate a naive per-layer early update.

Place frequent communication on fast links 48:56

Hybrid sharded data parallelism organizes workers into \(R\) replica groups of \(K\) shards, for \(RK\) workers. Within a group, weights and optimizer state are sharded. Across groups, corresponding shards represent replicas that must agree after gradient synchronization. This creates two communication axes with different requirements.

Full sharding communicates parameters for forward and backward as well as gradients; replicated data parallelism primarily synchronizes gradients. The lecture's “three versus one model copies” comparison identifies communication categories, not an exact count of bytes crossing every wire. Collective algorithms, precision, reuse of gathered parameters, and group size change the detailed volume. Nevertheless, it motivates placing sharding groups within a fast server or tightly connected pod, with replication across slower links.

Suppose our eight-device system consists of two four-device servers. A two-by-four hybrid layout shards state four ways inside each server. A globally sharded layout shards eight ways and uses less persistent memory per device, but requires more frequent communication across the server boundary. Neither wins universally. If activations dominate memory, halving persistent state may scarcely help; if cross-server communication is slow, the hybrid layout may make much better use of the hardware.

Recompute activations using a specified schedule 52:41

Backpropagation needs forward values. For \(L\) comparable layers, retaining every layer activation takes \(O(L)\) activation memory. If we retain none except the input, we can recompute a prefix whenever backward needs an intermediate state. The sum \(1+2+\cdots+(L-1)=L(L-1)/2\) gives quadratic extra forward work. This saves memory but is usually a poor schedule for deep networks.

The lecture then introduces checkpoints and describes repeated prefix recomputation inside blocks. If there are \(C\) evenly spaced checkpoints and constant temporary storage within each block, the total repeated-prefix work is \(O(L^2/C)\). Do not confuse the number of checkpoints with their spacing. This cost describes that particular recomputation strategy, not every method called activation checkpointing.

A useful research extension is to retain \(C\) block boundaries, then, during backward, recompute one whole block and temporarily retain its internal activations. Each block has about \(L/C\) layers. Its backward pass frees those temporary values before the previous block is reconstructed. Peak activation storage scales as

\[M_{\mathrm{act}}=O(C+L/C),\qquad C\approx\sqrt L\quad\Longrightarrow\quad M_{\mathrm{act}}=O(\sqrt L).\]

Each layer is recomputed only once under this simplified schedule, so extra forward work is \(O(L)\). This is the essential improvement discussed by Chen and colleagues. For 100 equal-cost layers, ten block boundaries and roughly ten internal states require about twenty activation-sized units rather than one hundred, ignoring boundary constants. The extra cost is approximately one forward traversal, not a hundred independent traversals.

Recomputation must reproduce the function used originally. A dropout mask regenerated differently changes the gradient. Mutable state, random generators, and nondeterministic kernels need a clear contract. Actual layers also have different activation sizes and costs, so uniform spacing is a teaching model. Checkpoint a cheap, memory-heavy region when it helps the actual memory bottleneck; do not assume every layer is equally valuable to recompute.

Measure useful work with an honest denominator 58:13

Hardware FLOPs utilization measures realized arithmetic relative to peak capability. Model FLOPs utilization, or MFU, counts the useful model forward-and-backward work rather than rewarding extra recomputation. Let \(F_{\mathrm{model}}\) be that work per global optimizer step, \(G\) the device count, \(P_{\mathrm{peak}}\) peak FLOP/s per device at the relevant precision, and \(t_{\mathrm{step}}\) measured step time. Then

\[\mathrm{MFU}=\frac{F_{\mathrm{model}}}{G P_{\mathrm{peak}}t_{\mathrm{step}}}.\]

A hypothetical step requiring \(8\times10^{14}\) model operations on four devices rated at \(10^{15}\) FLOP/s each takes 0.5 s, giving MFU \(0.4\). If checkpointing adds arithmetic but the same useful step still takes 0.5 s, MFU stays 0.4. Hardware utilization could rise because more work was executed. That is why the distinction matters.

PaLM and the Llama report provide primary context for this measurement. The lecture's reported percentages are workload-specific examples, not a universal ceiling or a pass mark for every architecture. A newer device can lower the fraction while reducing elapsed time if its theoretical peak grows faster than the workload can exploit it. Sparse versus dense peak rates, numerical format, and FLOP-count conventions must match the numerator.

GPU launches are asynchronous. A CPU timer around a launch can measure submission rather than completion. Use suitable device timing or synchronization, warm up kernels, and include the work intended by “step.” For practical model selection, also measure time to a target validation quality and cost. Inflating batches or wasting tokens merely to raise MFU can make the overall experiment worse. First choose a valid statistical workload; then improve its execution.

Long sequences need cross-token communication 63:17

A transformer layer operates on a tensor of shape \(B\times S\times D\): batch, sequence positions, and feature width. Context parallelism divides positions of the same sequence among devices. Token-wise feedforward functions and normalizations can be evaluated locally when the required parameters are available. Affine layer normalization does have learned parameters, despite a simplified slide description; replicated parameter gradients must still be combined.

Attention is harder because a query may need keys and values from every permitted position. Applying attention independently within each shard silently changes the model's receptive field. Ring Attention circulates key/value blocks while accumulating blockwise attention results. Ulysses uses all-to-all communication to redistribute sequence-sharded tensors into head-oriented layouts for attention, then redistributes the output. Neither is simply “split the input and concatenate predictions.”

This connects directly to our long factory videos. A defect at the end of one shard may depend on a tool interaction in another. A sharding scheme must preserve that interaction and its normalization. Positional indices and causal masks must use global sequence coordinates. Padding and uneven sequence partitions also affect gradient normalization. The placement changes; the intended attention relation should not.

Pipeline layers while preserving parameter versions 66:05

Pipeline parallelism places successive layers on successive devices. Activations travel forward across boundaries and activation gradients travel backward. A single microbatch uses stages sequentially, leaving most stages idle. The idle time is called a pipeline bubble. GPipe addresses this by splitting a batch into microbatches whose computations can occupy different stages concurrently.

For \(p\) equal-time stages and \(m\) microbatches, a simple fill-and-drain schedule has ideal utilization

\[U=\frac{m}{m+p-1}.\]

With four stages and four microbatches, \(U=4/7\approx57.1\%\), agreeing with the lecture's schedule. This fraction describes scheduled useful slots under simplified equal-stage assumptions; it is not the measured MFU of the hardware. Slow stages, communication, recomputation, and inefficient kernels lower actual performance.

Increasing \(m\) shrinks the bubble but can raise activation residency or reduce each matrix multiply's efficiency. A synchronous accumulated update must use the appropriate consistent parameter version for all contributing microbatches. Updating a stage while other microbatches still depend on its old weights changes the algorithm unless a deliberate versioning scheme handles it. Pipeline design is therefore both a scheduling problem and a differentiation problem.

Partition a matrix product by algebra 69:10

Tensor parallelism divides the computation within a layer. Let \(X\in\mathbb R^{n\times d}\), \(W\in\mathbb R^{d\times h}\), and \(U\in\mathbb R^{h\times o}\). Split \(W=[W_1\ W_2]\) by columns and \(U=[U_1^\top\ U_2^\top]^\top\) by rows. For an elementwise nonlinearity \(\phi\),

\[Z=\phi(XW)U=\phi(XW_1)U_1+\phi(XW_2)U_2.\]

Each worker computes one term without gathering the intermediate hidden features. Their output contributions must then be summed. This is the two-layer feedforward arrangement associated with Megatron-LM. The algebra relies on elementwise \(\phi\); a normalization that mixes all hidden coordinates would require additional communication. Add a shared output bias once after summation, not once per partial result.

Unlike full sharding that gathers a layer before each worker computes it on separate examples, tensor parallelism leaves each worker responsible for part of the layer's arithmetic on the same examples. These mechanisms can coexist with pipeline and context parallelism. A four-dimensional layout with degrees \(8,16,16,8\) contains \(16,384\) workers. Their product is an accounting identity; arranging those axes on physical links is an engineering decision. The best placement keeps the most latency-sensitive communication close while meeting memory limits.

An executable check of the algebra

The following CPU example verifies unequal-batch averaging and the two-layer tensor partition. It also checks independent arithmetic for collective cost, pipeline occupancy, checkpoint storage, and MFU. It is not a distributed benchmark. Save it beside the companion lab or run the code directly with NumPy. A failed equality would invalidate the proposed partition before any expensive cluster run.

import numpy as np

# Gradients for squared-error regression at the SAME weights.
x = np.array([[1., 2.], [2., -1.], [0., 3.], [4., 1.]])
y = np.array([1., -2., 2., 3.])
w = np.array([0.5, -0.25])
def grad(a, b):
    return a.T @ (a @ w - b) / len(b)
global_g = grad(x, y)
weighted_g = (3 * grad(x[:3], y[:3]) + grad(x[3:], y[3:])) / 4
wrong_g = (grad(x[:3], y[:3]) + grad(x[3:], y[3:])) / 2
assert np.allclose(global_g, weighted_g)
assert not np.allclose(global_g, wrong_g)

W = np.array([[1., -2., 3., 0.], [2., 1., -1., 2.]])
U = np.array([[1., 2.], [0., -1.], [3., 1.], [2., 0.]])
relu = lambda a: np.maximum(a, 0.)
full = relu(x @ W) @ U
partial = relu(x @ W[:, :2]) @ U[:2] + relu(x @ W[:, 2:]) @ U[2:]
assert np.allclose(full, partial)
assert np.isclose(2 * 3 * 10e-6 + 2 * 3 / 4 * 100e6 / 10e9, 0.01506)
assert np.isclose(4 / (4 + 4 - 1), 4 / 7)
assert 10 + 100 / 10 == 20
assert np.isclose(8e14 / (4 * 1e15 * 0.5), 0.4)
print("Weighted gradients, tensor partition, and system arithmetic passed.")

For an actual training test, compare one distributed update against a single-process update on the same tiny global batch. Compare losses, gradients, and updated parameters within tolerances. Then exercise uneven final batches, masks, tied parameters, checkpointed stochastic layers, and restart behavior. These tests target algorithmic equivalence; performance measurements come after correctness.

Six problems with worked solutions

1. A mean of worker means

Worker A averages gradients \(1,3,5\); worker B has gradient \(9\). What happens if both workers get equal weight?

Solution. The local means are 3 and 9. Their unweighted mean is 6, while the intended four-example mean is \((1+3+5+9)/4=4.5\). Weighting by counts gives \((3\cdot3+1\cdot9)/4=4.5\). Equal weighting instead optimizes a distribution assigning half the probability to worker B's single example.

2. Will sharding make the model fit?

A model has two billion parameters at 16 persistent bytes per parameter. Activations and temporary buffers require another 12 GB per device. Compare replication and ideal four-way sharding on a device with 24 GB usable capacity.

Solution. Replication needs \(32+12=44\) GB, so it fails. Ideal sharding needs \(32/4+12=20\) GB, leaving 4 GB. This is only a feasibility estimate: gathered parameter groups and allocator peaks must fit inside that margin. Sharding parameters does not divide the 12 GB activation term automatically.

3. A communication floor

A ring all-reduce uses eight workers, a 200 MB buffer, effective bandwidth 20 GB/s, and per-step latency 5 microseconds. Estimate the time under the chapter's model.

Solution. The latency term is \(2(8-1)5\cdot10^{-6}=70\) microseconds. The byte term is \(2(7/8)(200\cdot10^6)/(20\cdot10^9)=0.0175\) s. Total time is 17.57 ms. A 10 ms backward computation cannot fully hide this communication in that simplified model, even with perfect overlap.

4. Checkpoint count versus block size

For 144 equal layers, minimize the continuous approximation \(C+144/C\). What changes if every internal activation is discarded again during reconstruction?

Solution. Differentiating gives \(1-144/C^2=0\), so \(C=12\), and the storage proxy is 24 units. Retaining one reconstructed block permits linear total extra forward work. Discarding its internals forces repeated prefixes within each block, yielding approximately \(O(144^2/C)\) work. The same checkpoint boundaries do not specify the same algorithm.

5. Shrinking a pipeline bubble

Four stages need at least 80% ideal fill-and-drain utilization. How many microbatches are required?

Solution. Solve \(m/(m+3)\geq0.8\), giving \(0.2m\geq2.4\), hence \(m\geq12\). This is a schedule bound. Twelve tiny microbatches can have worse kernels than fewer large ones; the target cannot substitute for measuring step time and memory.

6. MFU and a misleading improvement

The same global batch requires \(10^{15}\) model FLOPs on eight devices, each rated at \(10^{15}\) FLOP/s. Configuration A takes 0.4 s and B takes 0.5 s after more recomputation. Their measured hardware arithmetic utilization is higher for B. Which is faster for the intended work?

Solution. A has MFU \(1/(8\cdot0.4)=31.25\%\); B has \(1/(8\cdot0.5)=25\%\). A completes the fixed model update faster. B may still be necessary to fit the model or enable a different useful batch, but extra executed FLOPs alone are not evidence of improvement. A fair comparison must state whether workload and validation behavior remained fixed.

From one correct update to a useful experiment

Our inspection model has not become statistically better merely because it spans more devices. Distribution makes a chosen computation feasible and efficient. Data parallelism partitions examples, context parallelism partitions positions, pipeline parallelism partitions layers, and tensor parallelism partitions internal matrix operations. State sharding and activation checkpointing address different memory terms. Their combinations work when gradients, parameter versions, and communication schedules preserve the intended computation.
